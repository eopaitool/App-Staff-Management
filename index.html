PRD: Staff Manage App — Phase 1 (Site AIS)

Version: 1.0 Date: 2026-05-20 Owner: G-able (Site AIS Team) Status: Ready for Implementation

1. Problem Statement

ปัจจุบันการจัดการพนักงาน outsource ของ G-able ที่ทำงาน on-site ที่ลูกค้า (เริ่มจาก Site AIS, ~39 คน) ทำผ่านเอกสาร Excel แบบ manual ทั้งหมด ทำให้เกิดปัญหา:

  1. การลงเวลาทำงาน (Time-attendance) ไม่มีการ verify ว่าพนักงานอยู่ที่ทำงานจริง — เกิดปัญหา "ฝากเพื่อนลงชื่อ" (buddy punching) ได้ง่าย
  2. การขออนุมัติวันลา ใช้กระดาษ/อีเมล ไม่มีการเช็ค quota แบบ real-time ทำให้เกิดการขอเกินสิทธิ์โดยไม่ตั้งใจ และ Admin ต้องคำนวณเอง
  3. การส่ง Timesheet รายเดือน พนักงานต้องกรอก Excel เองตามที่จำได้ ผิดพลาดบ่อย และ Admin ต้องตรวจสอบรายคน ก่อนส่งให้ PRTR ทุกสิ้นเดือน
  4. ไม่มี audit trail ที่ตรวจสอบได้ว่าใคร check-in/out เมื่อไหร่ และที่ไหน
  5. OT คำนวณยากเพราะต้องดูเวลาเข้า-ออกย้อนหลังจาก Excel หลายไฟล์

ทีม PRTR (บริษัทผู้บริหารจัดการ outsource) ต้องการ timesheet ที่ครบถ้วน ตรงตาม format มาตรฐาน และส่งทันเวลาทุกสิ้นเดือนเพื่อใช้ทำ payroll

2. Solution

สร้าง Staff Manage App เป็น web application ที่:

  1. ให้พนักงาน check-in/check-out ผ่านมือถือ โดยมีการ verify ตำแหน่ง GPS (อยู่ในรัศมีของสถานที่ทำงาน) และผูกกับ device ที่ลงทะเบียน
  2. ให้พนักงาน ขอลา ผ่านระบบ ดู quota เหลือ real-time และให้ Admin approve/reject ผ่านระบบเดียวกัน
  3. Generate Timesheet รายเดือนอัตโนมัติ จากข้อมูล check-in/out + ให้พนักงานใส่ OT manual + ค่าเบี้ยเลี้ยง
  4. Export ใบลงเวลาในรูปแบบ Excel ตรงกับ template ของ PRTR Site AIS เป๊ะ และ convert เป็น PDF เก็บใน Google Drive อัตโนมัติ
  5. ทุก action มี audit log ตรวจสอบได้
Technology Stack Google Apps Script (Web App) + Google Sheet (data) + Google Drive (files) + Gmail (notification)
MVP Scope Site AIS เท่านั้น (~39 คน) — ขยาย site อื่นใน Phase 2

3. User Stories (53 stories)

A. Authentication & Onboarding (7 stories)

  1. As an Admin, I want to เพิ่มพนักงานใหม่เข้าระบบ (email, ชื่อ, รหัสพนักงาน, ตำแหน่ง, site, workplaces, shift, start date), so that พนักงานสามารถ login เข้าใช้งานระบบได้
  2. As an Admin, I want to mark พนักงานว่ามี role เป็น Backfill, so that พนักงานคนนั้นสามารถถูก assign ให้ check-in ที่ workplace ของ site อื่นได้
  3. As an Employee, I want to login เข้าระบบด้วย Google account ของบริษัท, so that ไม่ต้องจำ password เพิ่ม
  4. As an Employee, I want to ลงทะเบียน device ตัวเองในการ login ครั้งแรก, so that ระบบรู้ว่าเครื่องไหนเป็นของผม
  5. As an Employee, I want to ระบบ auto-logout หลังไม่ได้ใช้งาน 8 ชั่วโมง, so that ลดความเสี่ยงคนอื่นมาใช้เครื่องผมต่อ
  6. As an Employee, I want to ขอ reset device ผ่าน Admin เมื่อเปลี่ยนเครื่องหรือเครื่องหาย, so that ใช้งานต่อได้
  7. As an Admin, I want to reset device binding ของพนักงาน, so that พนักงานที่เปลี่ยนเครื่องสามารถ register เครื่องใหม่ได้

B. Check-in / Check-out (8 stories)

  1. As an Employee, I want to กดปุ่ม Check-in ครั้งเดียว, so that ระบบ auto-detect workplace ที่ใกล้ที่สุดและบันทึกเวลา
  2. As an Employee, I want to ระบบ block การ check-in เมื่อ GPS อยู่นอกรัศมีของ workplace ทุกที่ที่ผมถูก assign, so that ป้องกันการ check-in นอกที่ทำงาน
  3. As an Employee ที่เป็น Backfill, I want to check-in ที่ workplace ของ site อื่นที่ Admin assign ให้ได้, so that สามารถไปทดแทนพนักงาน site อื่นได้
  4. As an Employee, I want to กด Check-out ตอนเลิกงาน, so that ระบบบันทึกเวลาออก
  5. As an Employee, I want to ได้รับ email แจ้งทุกครั้งที่ check-in สำเร็จ, so that รู้ทันทีถ้ามีคนสวมรอย
  6. As an Employee, I want to ดู check-in/out history ของตัวเอง, so that ตรวจสอบได้ว่าระบบบันทึกครบ
  7. As an Admin, I want to ดู check-in/out log ของพนักงานทุกคน, so that ตรวจสอบความผิดปกติได้
  8. As a system, I want to บันทึกทุก check-in attempt (สำเร็จและล้มเหลว) พร้อม timestamp, device, GPS, IP, so that มี audit trail

C. Leave Management (13 stories)

  1. As an Employee, I want to ขอลาผ่านระบบ (เลือก type, วันที่, ครึ่งวันได้, ระบุเหตุผล), so that ส่งคำขอไปให้ Admin
  2. As an Employee, I want to เห็น quota เหลือของแต่ละ type real-time, so that วางแผนการลาได้
  3. As an Employee, I want to ระบบหัก quota ทันทีตอนกด submit (pending), so that ไม่ขอซ้ำเกิน quota
  4. As an Employee, I want to ดูประวัติการลา (pending, approved, rejected), so that ตรวจสอบและจำได้
  5. As an Employee, I want to cancel คำขอลาที่ยัง pending ได้, so that ระบบคืน quota ให้
  6. As an Employee, I want to ขอลาป่วยย้อนหลังได้ (backdated), so that กรณีป่วยกะทันหันยังกรอกได้
  7. As an Employee, I want to ระบบ block การขอลาในวันหยุดประจำสัปดาห์ (เสาร์-อาทิตย์), so that ไม่กดผิดและเสีย quota
  8. As an Admin, I want to ดู list คำขอลาที่ pending, so that approve ได้ทั้งหมดในที่เดียว
  9. As an Admin, I want to approve หรือ reject คำขอลา พร้อมใส่เหตุผล, so that Employee เข้าใจการตัดสินใจ
  10. As an Admin, I want to ระบบคืน quota ให้ Employee อัตโนมัติเมื่อ reject, so that ไม่ต้องคำนวณเอง
  11. As an Employee, I want to ได้รับ email + in-app notification ทันทีที่ Admin approve/reject, so that รู้ผลเร็ว
  12. As an Employee ที่เข้าใหม่กลางปี, I want to ระบบให้ quota แบบ pro-rated ตามเดือนที่เหลือ, so that ไม่ได้ quota เต็มอย่างไม่เป็นธรรม
  13. As a system, I want to reset quota ทุก 1 มกราคม (วันที่เหลือถูก forfeit), so that เริ่มปีใหม่ตามมาตรฐาน

D. Timesheet (15 stories)

  1. As an Employee, I want to ดู timesheet preview ของเดือนปัจจุบัน, so that ตรวจสอบความถูกต้องระหว่างเดือนได้
  2. As an Employee, I want to ระบบ auto-generate timesheet rows จาก check-in/out ทุกวัน, so that ไม่ต้องกรอกซ้ำ
  3. As an Employee, I want to edit เวลาออก (check-out) ของวันที่ลืมกด check-out เอง พร้อมระบุเหตุผล, so that timesheet ถูกต้อง
  4. As an Employee, I want to request adjustment สำหรับวันที่ลืม check-in (ต้องให้ Admin approve), so that timesheet ครบ
  5. As an Employee, I want to ใส่ OT ในแต่ละวัน โดยระบุเวลาเข้า-ออก OT และเลือก rate (x1, x1.5, x2, x3), so that ได้รับค่า OT ตาม rate ที่ถูกต้อง
  6. As an Employee, I want to ใส่ค่าเบี้ยเลี้ยง TAXI ในแต่ละวัน (จำนวนเงินบาท), so that เบิกค่ารถได้
  7. As an Employee, I want to ใส่รายละเอียดงานในแต่ละวัน (optional), so that ระบุงานที่ทำได้
  8. As an Employee ที่เป็น Backfill, I want to ระบบ auto-fill "Onsite [SiteName]" ในช่องรายละเอียดงาน เมื่อ check-in ที่ workplace ของ site อื่น, so that ไม่ต้องพิมพ์เอง
  9. As an Employee, I want to submit timesheet ของเดือนทั้งเดือนในครั้งเดียว, so that ส่งให้ Admin approve
  10. As an Employee, I want to ได้รับ reminder ใกล้ deadline ทุกเดือน, so that ไม่ลืม submit
  11. As an Admin, I want to ดู list timesheet ที่ pending approval, so that approve ได้ทั้งหมดในที่เดียว
  12. As an Admin, I want to approve adjustment request สำหรับวันที่ Employee ลืม check-in, so that timesheet ครบถ้วน
  13. As an Admin, I want to approve timesheet แต่ละคน (หรือ batch), so that เสร็จเร็ว
  14. As an Admin, I want to reject timesheet พร้อม comment, so that Employee แก้แล้ว submit ใหม่
  15. As an Employee, I want to ได้รับ notification เมื่อ timesheet ถูก approve, so that รู้ว่าเรียบร้อย

E. Export & PDF (6 stories)

  1. As an Admin, I want to upload ลายเซ็นของตัวเอง (image) ครั้งเดียวตอน setup, so that ระบบใช้ฝังในไฟล์ export
  2. As a system, I want to generate ไฟล์ xlsx ตาม template AIS หลัง Admin approve timesheet, so that ส่งให้ PRTR ได้ทันที
  3. As a system, I want to ฝังลายเซ็น Admin ลงในช่อง "หัวหน้างาน" ของไฟล์ export โดยอัตโนมัติ, so that ไม่ต้องเซ็นมือทุกใบ
  4. As a system, I want to convert xlsx เป็น PDF และเก็บใน Google Drive ที่ path /[YYYY]/[MM]/, so that Admin/Employee เปิดดูย้อนหลังได้
  5. As an Admin, I want to download xlsx และ PDF ของพนักงานคนใดก็ได้ในเดือนใดก็ได้, so that ส่งให้ PRTR หรือเก็บเป็นหลักฐาน
  6. As an Employee, I want to ดูและ download PDF timesheet ของตัวเองย้อนหลัง, so that เก็บเป็นหลักฐานส่วนตัว

F. Admin Master Data (4 stories)

  1. As an Admin, I want to จัดการ Site (เพิ่ม/แก้ — MVP มีแค่ AIS แต่ schema รองรับหลาย site), so that ขยายในอนาคตได้
  2. As an Admin, I want to จัดการ Workplace (พิกัด GPS + รัศมี) ของแต่ละ site, so that กำหนดที่ทำงานได้ถูกต้อง
  3. As an Admin, I want to assign Workplace ให้พนักงานแต่ละคน (>= 1 workplace), so that พนักงานสามารถ check-in ได้ที่ที่ assign
  4. As an Admin, I want to ดู audit log ทั้งระบบ, so that ตรวจสอบและรายงานได้

4. Implementation Decisions

Architecture Overview

LayerChoice
HostingGoogle Apps Script (Web App)
Data StorageGoogle Sheet (1 spreadsheet, หลาย sheets)
File StorageGoogle Drive — /StaffManageApp/Exports/[YYYY]/[MM]/
EmailGmail API (MailApp / GmailApp)
FrontendHTML + Vanilla JS หรือ light framework (Alpine.js / petite-vue), mobile-first
CryptoUtilities API (UUID, hashing)

Modules (12 modules)

1. AuthService Shallow

Google OAuth login, session management (8h timeout), device binding validation

Interface: login(email, deviceFingerprint), validateSession(sessionId), resetDevice(employeeId)

2. GeoFenceService Deep

คำนวณระยะทาง GPS → หา nearest workplace ใน radius (Haversine formula)

Interface: findNearestWorkplaceInRadius(currentLocation, workplaces[]) → Workplace | null

Pure function — ทดสอบง่ายและคุ้ม

3. EmployeeRepository Shallow

CRUD employee profile, assignment management

Interface: getById, getByEmail, create, update, listWorkplaces

4. CheckInService Mixed

Orchestrate check-in flow (device check → GPS check → record → notify)

Interface: checkIn(employeeId, deviceId, currentLocation), checkOut(employeeId)

5. LeaveQuotaCalculator Deep

คำนวณ quota เหลือ รวม pro-rated allocation + pending + approved

Interface: calculateRemaining(employee, leaveType, year, allRequests[]) → number

Pure function — edge case เยอะ ทดสอบคุ้ม

6. LeaveService Mixed

Submit / approve / reject / cancel leave + quota update + weekend validation

7. TimesheetAggregator Deep

รวม check-in events + manual edits + OT entries → TimesheetRow[]

Handle forgot check-out, backfill auto-fill, working hours calc

Pure function — snapshot test ได้

8. TimesheetService Mixed

Submit / approve workflow + edit rules (check-out edit allowed, check-in edit needs approval)

9. ExportRenderer Deep

Render timesheet data → xlsx ตำแหน่ง cells ของ AIS template + ฝัง admin signature

Snapshot test ของ cell values

10. PDFConverter Shallow

Convert xlsx → PDF + save to Drive

11. NotificationService Shallow

Email + in-app event dispatcher

12. AuditLogger Shallow

Append-only log สำหรับทุก action

6. Security Model

  1. Identity: Google OAuth (ผ่าน Apps Script Session.getActiveUser())
  2. Authorization: Email ต้อง match ใน Employees.email
  3. Device Binding:
    • First login → generate UUID v4 → save localStorage + Devices sheet
    • Subsequent: client ส่ง UUID → server compare กับ Devices[employee_id]
    • Browser fingerprint (canvas hash + UA + screen) เก็บเสริม
  4. Session timeout: 8 ชั่วโมง
  5. Audit Log: ทุก auth event, check-in, leave/timesheet/admin action
  6. Anti-impersonation: Email alert ทุกครั้งที่ check-in สำเร็จ
  7. Recommended: บังคับ Google 2FA ผ่าน Google Workspace admin policy

7. Key Flows

Flow A: Employee Onboarding

Admin เพิ่ม Employee → save Employees sheet
   ↓
ระบบส่ง welcome email + link
   ↓
Employee คลิก link → Google login (verify email)
   ↓
ระบบเช็ค: ไม่มี device → แสดง "Register this device"
   ↓
Generate UUID + เก็บ localStorage + Devices sheet
   ↓
เปิดหน้า Dashboard

Flow B: Daily Check-in

Employee เปิด app → session validate
   ↓
หน้าหลักแสดงปุ่ม "Check-in"
   ↓
กดปุ่ม → request GPS permission → ได้ coordinate
   ↓
ส่ง check-in request (employee_id, device_uuid, lat, lng)
   ↓
Server:
  1. Validate session ยัง active
  2. Validate device_uuid match
  3. GeoFenceService.findNearestWorkplaceInRadius()
  4. ถ้า null → return blocked + log
  5. ถ้าเจอ → append CheckInEvents
  6. ส่ง email notify + in-app notify
   ↓
Client แสดง "Check-in สำเร็จ at [Workplace]"

Flow C: Leave Request → Approval

Employee เปิดหน้า "ขอลา"
   ↓
เลือก type, dates, half-day config → submit
   ↓
Server:
  1. Validate dates ไม่ใช่วันหยุดประจำสัปดาห์
  2. LeaveQuotaCalculator.calculateRemaining → >= days_count
  3. append LeaveRequests (status=pending)
  4. ส่ง notify Admin
   ↓
Admin approve / reject (พร้อม reason)
   ↓
Server update + notify Employee

Flow D: Monthly Timesheet

ตลอดเดือน: CheckInEvents auto-populate
   ↓
วันที่ 25: ระบบส่ง reminder email
   ↓
Employee เปิด "Timesheet" → TimesheetAggregator แสดง rows
   ↓
Employee: edit, request adjustment, ใส่ OT, taxi, work desc
   ↓
กด Submit → status=pending
   ↓
Admin approve
   ↓
Server:
  1. ExportRenderer.render → xlsx (ฝัง signature)
  2. save Drive: /StaffManageApp/Exports/2026/05/
  3. PDFConverter.convertAndStore → PDF
  4. update TimesheetSubmissions
  5. notify Employee

Flow E: Backfill Check-in

Admin: Toggle "Backfill eligible" + เพิ่ม AJI workplace
   ↓
Employee check-in ตามปกติ (Flow B)
   ↓
GeoFenceService หา workplace ใกล้สุด → เจอ AJI
   ↓
ตอน aggregate timesheet:
  - check_in_workplace.site_id != home_site_id
  → auto-fill "Onsite AJI" ใน work_description

8. Testing Decisions

หลักการ

ทดสอบ external behavior ไม่ใช่ internal implementation Test คำตอบของ function ตาม input — ไม่ test ว่ามันเรียก function ไหน เปลี่ยน implementation ภายในแล้ว test ต้องไม่พัง ถ้า behavior เหมือนเดิม

Unit Test (Deep Modules)

1. GeoFenceService HIGH PRIORITY

  • GPS ตรงกลาง workplace → return workplace
  • GPS ที่ขอบ radius (ใน-นอก) → boundary correctness
  • GPS นอก radius ทุก workplace → return null
  • หลาย workplace ทับซ้อน → return nearest
  • Workplace ว่าง → return null

2. LeaveQuotaCalculator HIGH PRIORITY

  • Quota เต็ม → return ค่ามาตรฐาน
  • Approved request → หักถูก
  • Pending request → หักถูก
  • Rejected request → ไม่หัก
  • Half-day → หัก 0.5
  • เข้าใหม่ 1 ก.ค. → Annual = 3 (pro-rated)
  • Year boundary (30 ธ.ค. - 2 ม.ค.) → handle ถูก
  • Cancel pending → คืน quota

3. TimesheetAggregator HIGH PRIORITY

  • ไม่มี check-in เลย → ทุก row ว่าง
  • Check-in/out ปกติ → row ครบ
  • ลืม check-out → row มี checkmark
  • Manual edit เวลาออก → priority สูงกว่า raw event
  • Backfill day → auto-fill "Onsite [Site]"
  • OT entry ครบทุก rate
  • Multi-check-in → first in + last out

4. ExportRenderer MEDIUM PRIORITY

  • Render ทั้งเดือน → ทุก cell ตรง (snapshot)
  • OT หลาย rate → cells x1, x1.5, x2, x3 ถูก
  • Taxi amount → cell P ถูก
  • Admin signature → embedded ที่ Q44
